# BeiDou-Server 代码审查报告

> 审查日期：2026-09-08 · 审查方式：5 个专项并行深审（并发与线程安全 / 事务与数据一致性 / 安全 / 架构设计 / 功能正确性与资源），全部结论以源码为准并附 `文件:行号`；报告中的 P0 结论已由主审二次抽查复核。本报告只陈述问题与建议，未修改任何源码。
>
> 行号基准：当前工作区 `master@6c5a1c1f5`。路径省略前缀 `gms-server/src/main/java/org/gms/`（另行标注的除外）。

## 0. 总体结论

整体看，项目在「已修过的路径」上质量不错：五锁并发域锁序一致、Guild/Alliance 核心路径已事务化（FOR UPDATE 规范）、掉落热重载已用快照修复、Trade 握手机制成立、Netty ByteBuf 无泄漏、前端无 XSS。但审查共确认 **约 80 项问题**，其中 **8 项 P0**。三类系统性根因贯穿大多数发现：

1. **三种原子性级别混用**：同一 Druid 池上「Spring 事务 / 遗留 JDBC autocommit / 纯内存 + 1 小时 autosave 延迟落盘」并存，所有跨实体价值转移（交易、商店、快递、MTS、礼物）都横跨至少两个级别——崩溃窗口即复制或丢失。
2. **生命周期无契约**：`shuttingDown` 实例级标志 + 吞异常的 `Channel.shutdown` + 无超时等待 + 重启不清实例缓存，多路径叠加成「关了起不来」。
3. **信任边界模糊**：MTS 搜索直接拼接玩家可控字符串、JWT secret 出厂硬编码、GraalVM 脚本全开放宿主类，三者可串成完整攻破链。

## 1. P0 — 必须立即修复（8 项）

### P0-1 MTS 搜索 SQL 注入（玩家可控，游戏端口直接可达）
- `net/server/channel/handlers/MTSHandler.java:800`（拼接）、`:806/:808/:857`（执行）、`:261`（来源 `p.readString()`）
- `ci==0` 分支把玩家在 MTS 搜索框输入的 `search` 直接拼进 `LIKE CONCAT('%','<search>', '%')`。可注入读库/盲注/改数据，DB 连接默认是 root。
- **连锁利用**：① `UPDATE command_info` 把 `setgmlevel`/`shutdown` 等命令降到 level 0 → 全服玩家可执行（命令等级完全由 DB 热驱动）；② `UPDATE accounts SET webadmin=1` → 拿管理后台；③ 配合 `/file/v1/tree/write` 写脚本 + GraalVM 全开放 = RCE。
- 修复：参数化 `setString`；对 search 做长度/字符白名单。

### P0-2 MTS 购物车购买给卖家重复入账（直接 NX 复制）
- `MTSHandler.java:488-505`（case 17）
- 对**所有渠道循环**：卖家在线频道 `gainCash`，其余每个频道都再执行一次 `UPDATE accounts SET nxPrepaid = nxPrepaid + price`。频道数 N≥2 时卖家收 N 倍价款、买家只付一次。对照 case 16（`:430-451`）有正确的 `alwaysnull` 单次处理。
- 修复：去掉循环；整笔购买（扣买家/入卖家/转移 `mts_items`/删购物车）包进单事务，用受影响行数判定抢占。

### P0-3 JWT secret 使用仓库内出厂硬编码值
- `gms-server/src/main/resources/application.yml:9`、`util/JwtUtils.java`
- HS512 对称签名 + AGPL 公开仓库 + 注释自认「生产请自行生成」但无强校验。任何拿到源码者可对**所有未改默认值的部署**离线签发 admin token，通过全部 REST 管理接口（封号/发资源/写服务器文件/关服）。
- 修复：启动检测出厂值即拒绝启动（或强制环境变量）；secret ≥256bit 随机。

### P0-4 Duey 快递领取「先给后删」+ 异常吞掉 → 可重复领取
- `client/processor/npc/DueyProcessor.java:401-461`
- 顺序为 `addFromDrop`（内存）→ `gainMeso`（内存）→ DELETE（autocommit），DELETE 失败仅 `printStackTrace`——物品/金币已到手而快递仍在库，可再领。且方法无 `tryacquireClient`，与 autosave 交错时崩溃即双份。
- 修复：先事务内 `SELECT ... FOR UPDATE` + DELETE + 提交，成功后再给货；补 `tryacquireClient`。连带：`dueyRemovePackage`（`:389-398`）按包 ID 删库无属主校验，改包可删他人快递——DELETE 加 `AND ReceiverId = ?`。

### P0-5 HiredMerchant.buy 跨轨入账：买家内存扣款、卖家立即落库 → 崩溃即刷钱
- `server/maps/HiredMerchant.java:298-382`、`client/Character.java:8113-8124`
- 买家 `gainMeso(-price)` 仅内存（最长 1 小时窗口）；卖家在线走 MyBatis 立即 UPDATE、离线直接 DB UPDATE。崩溃后买家回滚、卖家已入账 = 净增发。交易末尾 `saveItems(false)`（`:377`）失败被吞 → DB 库存未扣，买家已拿货随存档保存 → 商店重开可再卖 = 复制。
- 修复：买家扣款、卖家入账、商店库存扣减放同一 DB 事务；或购买后强制 `saveCharToDB(false)` 且 `saveItems` 失败升级为致命重试（参考 `forceCloseInternal:443-446` 既有做法）。

### P0-6 `Server.init` 失败直接 `System.exit(0)`，共享故障域击穿管理台
- `net/server/Server.java:748-751`、`controller/ServerController.java:32-37`
- 游戏/REST/管理台同 JVM。在线 `/server/v1/startServer` 恢复游戏服时若 init 中途失败（DB 抖动、端口占用），`System.exit(0)` 连 Spring 容器和管理台一起杀掉——修复动作变成全服事故放大器，事后无管理台可用。
- 修复：init 失败置 `online=false` 并抛出记录，绝不 exit；中期目标进程分离。

### P0-7 重启链路不干净 + 关停可死锁挂死（「关了起不来」的完整根因链）
- 实例缓存残留：`Server.java:119-123`（`guilds`/`inLoginState`/`buffStorage`/`alliances`）在 stop→start 路径不清空（`resetServerWorlds():530-539` 只清 worlds/channels），`getGuild`（`:929-960`）重启后命中上一代 Guild 对象；静态 `activeFly`（`:104`）两条重启路径都不清。
- 重启竞态：`shuttingDown` 是**实例字段**（`:161`），restart 末尾 `instance = null` 后新实例标志已复位而 init（分钟级）仍在旧锁内——并发关停拿到半初始化实例 → `loginServer` NPE / 向已 shutdown 的 TimerManager 注册任务抛 RejectedExecution → 双重失败。`getInstance()`（`:95-102`）无同步且 `instance` 非 volatile，null 窗口可能造出两个实例。
- 关停挂死：`Channel.java:187-215` 的 `finishedShutdown=true` 在 `channelServer.stop()` 之后且整个方法吞异常（端口绑定失败时 `channelServer` 为 null 即必挂），`Server.java:1686-1694` 的 `while (!ch.finishedShutdown()) sleep(1000)` **无超时**，持 Server 锁永久自旋。
- 静态缓存重复：`CashShop.java:131/208` `cashCategories` 只 `addAll` 从不 clear，N 次重启含 N 份重复分类。
- 修复：`shuttingDown` 改静态 + 全局锁；init 移出关停锁；`getInstance()` 加同步；`Channel.shutdown` 用 finally 置位；等待循环加超时；重启语义统一为完整清空。

### P0-8 GameConfig 热重载与全服高频读并发：非线程安全 JSONObject 结构性修改
- `config/GameConfig.java:23`（`JSONObject properties`，底层 LinkedHashMap）、`:35-71`（add/remove 三层连环删）、`:295-303`（`getValue` 裸迭代 keySet）
- REST/GM 命令热增删配置的瞬间，任一游戏线程在 `getServerBoolean/getServerInt`（几乎每个 handler 都调）迭代 keySet → ConcurrentModificationException 打穿该玩家当前包处理；并发扩容可丢配置。
- 修复：照 `DropCache` 快照模式——写侧构建整棵新树后 volatile 整体替换，或收敛到读写锁。

## 2. P1 — 高优先级（16 项）

**数据一致性：**
1. **双轨事务互不感知**：`DatabaseConnection`（`util/DatabaseConnection.java:16`）绕过 Spring 事务同步。`CharacterService.deleteCharacterById`（@Transactional，`:250-344`）内嵌裸连接删经验日志（失败还吞掉继续）、`Server.deleteGuildCharacter` 散会——外层回滚时这些已独立提交/不可逆。`deleteAccount`（`:547-576`）在 Spring 事务内嵌套手写 JDBC 长事务 + 断线广播。
2. **Fredrick 取货先删后给**（`FredrickProcessor.java:275-330`）：`withdrawMerchantMesos` 立即落库 + `deleteFredrickItems` autocommit DELETE 后才 `addFromDrop` 入内存——中间崩溃 = 商店物品与销售收入双丢。
3. **MTS 提货（case 8，`MTSHandler.java:297-365`）**：先 DELETE 后给货、无背包空间校验、`addFromDrop` 返回值被忽略——背包满时提货 = 物品直接消失。
4. **CashShop 礼物**（`server/CashShop.java:414-465`）：`loadGifts` 把礼物入内存购物栏后立即 DELETE gifts 行，落盘要等 `saveCharToDB`（1 小时窗口）——崩溃即礼物丢失。
5. **换线异步存档竞态**（`Client.java:1078`、`Character.java:7601-7610`）：换线时保存注册成 200ms 后的异步任务后立即放行——新频道可能读到旧档，排队任务随后用旧实例快照覆盖新实例更新。
6. **saveCharToDB 旁路写入 + 降级隔离**（`Character.java:7617-8004`）：事务隔离降为 READ_UNCOMMITTED；`Pet.saveToDb`（`Pet.java:109-122`）用自己的连接在主事务外 autocommit——主事务回滚时宠物数据已提交，部分保存。

**并发：**
7. **MapleMap 延迟属性队列丢任务**（`MapleMap.java:126`、`:4575-4588`）：裸 `ArrayList` 的 copy-then-clear 与玩家线程 `add` 无同步——busy 图掉血高峰丢死亡判定/组队 HP 同步，或 CME/数组损坏。改 `ConcurrentLinkedQueue` 一行级修复。
8. **延迟死亡不复查 HP**（`Character.java:8155-8176`、`:6830-6896`）：`playerDead()` 无条件执行——200ms 窗口内被宠物药/治疗救回仍白扣经验、白吞护符、取消 buff。入口加 `if (hp > 0) return;`。
9. **Messenger 全链无同步**（`World.java:153/1241-1246/1104-1116`、`Messenger.java:47-61`）：裸 HashMap + 裸 ArrayList + check-then-act「size<3 判定」+ 活视图迭代——双接受挤爆房间、聊天与退出并发 CME。
10. **Guild.buildNotifications 锁外改锁内集合**（`Guild.java:137-155`）：`chl.add` 在 `synchronized(notifications)` 外；`bDirty` 非 volatile 可见性无保证。
11. **saveCharToDB 持 Character 监视器跑整段 JDBC**（`Character.java:7617`，autosaver 每 1 小时全服遍历）：慢存档拖住共享 Netty event loop 上**其他玩家**的封包处理——周期性全服卡顿的候选根因。

**安全：**
12. **REST 管理登录永久接受明文/SHA-1/SHA-512 旧哈希且不迁移**（`service/AccountService.java:181-188`）：游戏侧 `LoginPasswordHandler.java:85-96` 会当场重哈希 bcrypt，REST 侧 `checkPassword` 从不回写——存量弱哈希对管理后台永远有效；空密码字段 `charAt(0)` 抛越界。
13. **登录爆破防护薄弱**：游戏侧失败计数是连接级（`Client.java:656-661`，重连清零），IP 级防护被 `deterred_multi_client`（默认 false）门控（`SessionCoordinator.java:186-190`）；REST `/auth/v1/login` 无锁定，限流默认关（`application.yml:55`）。
14. **swagger 万能 token 后门**（`aop/AuthTokenFilter.java:49-55`）：已核实默认关闭（两个开关均 false），但一个配置失误 = admin 失陷，且 API 文档匿名可枚举。建议删除后门 + docs 路径加 Basic Auth。
15. **`use_debug + no_password` 免密直通**（`Client.java:693-694`，默认关）：开 debug 联动即全服免密 + 自动注册（默认 true）批量占号。
16. **伤害信任客户端 + autoban 默认关闭**（`AbstractDealDamageHandler.java:563/976-986`、`V1.7.0:233-234` `use_auto_ban=false`）：服务端算的 `maxWithCrit` 仅用于记点，从不 clamp——改包秒杀任意 Boss 无约束。

## 3. P2 — 中优先级（22 项）

**架构：**
1. `characters` 表双轨写入：44 条手写 SQL 散布 19 个文件（`Character.java:7626` 57 列 UPDATE、`CharactersMapper.java:19-22` 甚至有无 WHERE 的全表 `@Update`），与 75 字段 `CharactersDO` 无单一事实源，加列必漂移。
2. `CharacterService.saveCharToDB`（`:346-356`）是危险的死代码：同名但语义是 INSERT（`insertSelective`），误调用即插重复角色行。删除或改名+`@Deprecated`。
3. GraalVM JS 三重代价（`AbstractScriptManager.java:71/106-111`、`Client.java:129`）：每脚本新引擎（MB 级冷启动、随会话累积）+ `allowHostClassLookup` 全开（脚本可 `Java.type` 任意类，配合文件写入即 RCE）+ 4027 个脚本无版本管理。
4. 静态 ApplicationContext 服务定位器扩散 29 个文件，含 13 个 service 在 `Server` **类加载期** getBean（`Server.java:163-175`）——启动顺序脆弱、单测无法脱离容器。
5. `dao/entity/ModifiedCashItemDO.toItem()`（`:105-163`）内嵌游戏规则且是 CodeGen 生成物——下次重新生成会被覆盖丢失。持久层反向依赖领域层。
6. `ConfigService.importYml`（`:171-222`）：字符串拼接 SQL + 无条件整服 restart；`host`/`lanhost` 映射到不存在的 code 时静默 no-op 还白重启。
7. 每频道独立双 EventLoopGroup + 全内存拓扑（`net/netty/ChannelServer.java:24-25`）：满配 420 频道 ≈ 1.3 万常驻线程；水平扩展无路径——应作为明确的「不支持」架构决策记录。
8. i18n 三轨并存 + 游戏内硬编码广播（`MobDamageMobFriendlyHandler.java:57-69` 七条中文、`MTSHandler.java:125` 英文）——语言切换在这些文案上断链；`ServerController.java:56` 有 `System.out.println` 调试残留。

**并发（DropCache 同型未修 + 其他）：**
9. `ItemInformationProvider`（`:93-141` 约 35 个裸 HashMap 懒缓存）、`LifeFactory.monsterStats`（`:50/552-561`）、`MonsterInformationProvider`（`:64-70`）——开服刷怪高峰并发写裸 HashMap，与已修的 DropCache 完全同型。统一 `computeIfAbsent`。
10. `RateLimitUtil`（`util/RateLimitUtil.java:17-62`）：无界 HashMap 按永不删除的 IP 键增长 + 多 Netty 线程并发写 + `getInstance()` 无同步懒加载。
11. `BaseScheduler`（`services/BaseScheduler.java:96-179`）：到期执行与 `interruptEntry` 双重执行竞态（Reactor 延迟重生等受影响）；`dispose` 锁外清 `externalLocks`。
12. `Trade` 读侧无锁（`Trade.java:256-258/193-195`）：跨线程拷贝与 `addItem`（不检查 locked）并发 CME；`Character.trade`（`:334`）非 volatile。握手防线本身成立。
13. `Reactor`（`:351-355/336-341`）：`timeoutTask` 跨线程无锁写；脚本在 hitLock+reactorLock 双锁内执行任意 JS——可重入死锁候选。
14. `TimerManager/ThreadManager`（`TimerManager.java:45-96`、`ThreadManager.java:36-42`）：`ses`/`executor` 非 volatile，重启窗口向已 shutdown 的 executor 提交抛未捕获 RejectedExecutionException。
15. `HiredMerchant.buy` 持 items 监视器做 JDBC/背包写/发包三件重活（`:298-381`）——DB 抖动即全店排队，违反项目自己确立的「锁内不做 I/O」原则。
16. `Guild.createGuild`（`Guild.java:~495-513`）仍是两条 autocommit（INSERT guilds + UPDATE characters），中间崩溃留孤儿公会；成员逐行更新与内存发散（对照已修好的 `disbandOnDb` 事务化写法）。
17. `ItemFactory` 条带锁不覆盖调用方提交点（`ItemFactory.java:205-308`）：同账号两角色并发保存 STORAGE 条目可交错。
18. `updateRate` 越权（`CharacterController.java:27-31`、`CharacterService.java:137-177`）：`extendId` 全由请求体指定、无属主校验——任意登录用户可给任意角色设个人倍率。
19. GM 删除在线角色与异步断线保存竞态（`CharacterService.java:582-596`、`Client.java:981-983`）：`forceDisconnect` 失败时删除事务与在途保存并发。
20. `Trade`/`HiredMerchant.closeShop`（`:527-584`）结算忽略 `addFromDrop` 返回值 + 关店 `saveItems` 失败被吞 → DB 残留可经 Fredrick 二次取回。
21. `CashShop.save`（`:476-481`）用内存快照无条件覆盖 accounts 三个 NX 字段，与 REST 后台并发加款互相丢更新。
22. REST 权限「全有或全无」：`@EnableMethodSecurity` 已开但全仓 0 处 `@PreAuthorize`，停服/写文件/删号无细分（`ServerController.java:31-37` 的 GET `/shutdown` 直接 `System.exit(0)`）。
