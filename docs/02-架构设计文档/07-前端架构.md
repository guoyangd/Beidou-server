# 07 前端架构（gms-ui）

> 模块路径：`gms-ui/`（核心在 `src/`、`config/`、`.env.*`）
> 涉及文件数：约 30 个核心文件（`src/api/*` 17 个、`src/router/guard/*` 3 个、`src/store/modules/*` 9 个模块等）
> 依赖模块：后端 `gms-server` REST API（8686，`ResultBody`/`SubmitBody` 信封、JWT 鉴权，见《06-安全架构》）

## 3. API 层约定（`src/api/interceptor.ts`）

`main.ts` 以 `import '@/api/interceptor'` 副作用注册全局 axios 拦截器，所有 `src/api/*.ts` 直接 `axios.post/get/...`，不单独创建实例。

### 3.1 baseURL

```ts
if (import.meta.env.VITE_API_BASE_URL) {
  axios.defaults.baseURL = import.meta.env.VITE_API_BASE_URL;
}
```

dev 由 `.env.development` 指向 `http://localhost:8686`；prod `.env.production` 为空 → 相对路径同源请求。

### 3.2 请求拦截器（与后端 `SubmitBody<T>` 信封对齐）

- 从 `getToken()`（`utils/auth.ts`，localStorage `token`）取 JWT，自动加 `config.headers.Authorization = 'Bearer ' + token`。
- **自动包信封**：若 `config.data` 存在且非上传（`Content-type !== 'multipart/form-data'`），把 data 重写为：

```ts
{ requestId: generateUUID(), data: <原data> }   // 对应后端 SubmitBody<T>（requestId/data）
```

  `generateUUID()` 为文件内实现的 v4 UUID。因此各 api 文件只传业务对象，无需手工包 requestId。路径统一带版本段，如 `/auth/v1/login`、`/account/v1/info`（与后端 `ApiConstant.LATEST` 约定一致）。

### 3.3 响应拦截器

- **blob 下载**：`response.config.responseType === 'blob'` 时走文件下载分支——`URL.createObjectURL` 生成临时链接，从 `Content-Disposition` 头 `split('filename=')[1]` 取文件名（去引号），创建 `<a download>` 触发点击后释放 URL 对象，返回 `null`。
- **业务码判定**：`res.code !== 20000`（后端 `BizExceptionEnum.SUCCESS`）即失败，`Message.error` 展示 `res.message` 并 `Promise.reject`。
- **网络/HTTP 错误分支**：`Network Error` 显示「无法连接到服务器」；其余展示 `error.message`。
- **401 登出**：HTTP 状态 401（后端 `AuthEntryPointJwt`）时调用 `useUserStore().logoutCallBack()` 清理本地状态，并 `window.location.href = '/'` 跳回首页（登录页）。

```mermaid
flowchart LR
    View[组件 / store] -->|axios.post('/xxx/v1/yyy', data)| ReqInt[请求拦截器]
    ReqInt -->|加 Bearer token| Env["包信封 {requestId: uuid, data}<br/>(multipart 上传不包)"]
    Env --> Srv[gms-server 8686]
    Srv -->|ResultBody / Blob| ResInt[响应拦截器]
    ResInt -->|code === 20000| OK[返回 res]
    ResInt -->|code !== 20000| Err[Message.error + reject]
    ResInt -->|responseType=blob| File[Content-Disposition 取文件名触发下载]
    ResInt -->|HTTP 401| Out[logoutCallBack + 跳转首页]
```

## 4. 路由与守卫（`src/router/guard/`）

`router/index.ts` 创建路由后调用 `createRouteGuard(router)`（`guard/index.ts`），按顺序注册三层 `beforeEach`：

1. **`setupPageGuard`**：仅 `setRouteEmitter(to)` 通过 mitt 发出路由变更事件（供 layout/tab-bar 监听）。
2. **`userLoginInfo.ts`（登录守卫）**：
   - `NProgress.start()`；
   - `isLogin()`（localStorage 有 token）且 `userStore.role` 已有 → 直接放行；role 未加载 → `await userStore.info()` 拉取用户信息，失败则 `logout()` 并重定向 `login`（携带 `redirect` query 回跳）。
   - 未登录 → 非-login 页一律重定向 `login`。
3. **`permission.ts`（权限守卫）**：
   - `usePermission().accessRouter(to)` 按角色（`userStore.role`）判断路由 `meta.roles` 是否可访问；
   - `appStore.menuFromServer` 模式下在 `appAsyncMenus` + `WHITE_LIST` 中做 BFS 存在性校验，不存在或无权限 → `NOT_FOUND`；
   - 本地路由模式下无权限则跳到 `findFirstPermissionRoute(appRoutes, role)`（该角色首个可用页）或 `NOT_FOUND`。

```mermaid
flowchart TD
    Nav[路由跳转 to] --> P1[PageGuard: 发路由事件]
    P1 --> P2{isLogin 且有 token?}
    P2 -- 否 --> Login[重定向 login 带 redirect]
    P2 -- 是 --> P3{userStore.role?}
    P3 -- 无 --> Info[userStore.info 拉取<br/>失败则 logout + login]
    P3 -- 有 --> P4{Permission.accessRouter(to)}
    P4 -- 允许 --> Next[next 放行, NProgress.done]
    P4 -- 拒绝 --> P5[首个有权限路由 或 NOT_FOUND]
```

## 5. 状态管理（`src/store/modules/`，Pinia）

共 9 个模块，`store/index.ts` 统一导出 `useXxxStore`：

| 模块 | 职责 |
|---|---|
| `user` | 登录态：token、role、`info()`（调 `/account/v1/info`）、login/logout、`logoutCallBack`（401 时前端清理回调） |
| `app` | 全局 UI 设置：主题、语言、菜单来源（`menuFromServer`、`appAsyncMenus` 服务端菜单） |
| `tab-bar` | 多标签页栏状态 |
| `account` | 账号管理页（目前仅 `types.ts`，逻辑在 `src/api/account.ts` + 视图内） |
| `cashShop` | 商城管理 |
| `drop` | 掉落管理 |
| `gachapon` | 转蛋机管理 |
| `inventory` | 物品/库存管理 |
| `npcShop` | NPC 商店管理 |

模式约定：跨页面共享或需缓存的业务状态进 `store/modules/<模块>/`（`index.ts` + `types.ts`）；一次性的请求直接在视图里调 `src/api/<模块>.ts`。页面级 Pinia 写法另见 `store/page.ts`。

## 6. 部署模型

```mermaid
flowchart TB
    subgraph Dev[开发模式 yarn dev :8787]
        Browser1[浏览器 :8787] -->|VITE_API_BASE_URL 跨域| Cors[CorsConfig<br/>放行 app.vue: http://localhost:8787]
        Cors --> Api1[Spring Boot :8686]
    end
    subgraph Prod[生产模式 yarn build]
        Dist["dist/ (vue-tsc + vite build)"] -->|拷贝| Static["gms-server/src/main/resources/static/"]
        Browser2[浏览器 :8686] -->|同源静态资源 / /assets/**| Static
        Browser2 -->|相对路径 /auth /xxx/v1 同源| Api2[Spring Boot :8686<br/>SecurityConfig 放行 / index.html /assets/**]
        Api2 -.启动时检测 static/index.html.-> Prompt[ServerManager 提示前端地址]
    end
```

- **dev**：`.env.development` 设 `VITE_API_BASE_URL='http://localhost:8686'`，前端 8787 直连后端，跨域依赖后端 `CorsConfig`（`application.yml` 的 `app.vue` 配置项，默认 `http://localhost:8787`）。
- **prod**：`.env.production` 为空 → 请求走相对路径；`yarn build`（先 `vue-tsc --noEmit` 再 `vite build --config ./config/vite.config.prod.ts`）产出 `dist/`，拷入 `gms-server/src/main/resources/static/`，随 `BeiDou.jar` 由 8686 端口**同源托管**。`manager/ServerManager.java` 启动时检测 classpath `static/index.html` 是否存在，决定是否提示前端访问地址。
- 同源托管后无 CORS 问题，`SpringSecurityConfig` 已放行 `/`、`/index.html`、`/static/**`、`/assets/**`；Monaco 资源仍走 unpkg CDN，内网部署需留意（`main.ts` 中备有 jsdelivr/bootcdn 注释行可切换）。

## 7. 新增一个后台页面的约定路径

1. 后端新增 controller 接口（版本路径 `/{模块}/{ApiConstant.LATEST}/{action}`）。
2. `src/api/<模块>.ts` 新增函数，直接 `axios.post`，只传业务 data（信封由拦截器自动包）。
3. 需要共享状态则在 `src/store/modules/<模块>/` 建模块，否则跳过。
4. `src/router/routes/modules/` 加路由（`meta.roles` 控制权限），`src/views/<模块>/` 写页面；界面文本走 `src/locale` 的 `t()`，禁止硬编码。
