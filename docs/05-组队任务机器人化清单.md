- 宝箱开启仍由玩家交互驱动，天然不受 bot 刷分影响；后续若做 PPQ 机器人陪打，建议给 bot 关闭奖励发放。

## 3.3 奖励表意义判定（机器人经济 review 结论）

前提澄清：BeiDou 功能 NPC（9900001）菜单里的「一键刷道具」**仅 GM 可见**（`isGM()` 门控），不构成对玩家经济的否定。

机器人经济的实际形态：FM 商人 bot 是一套模拟装备市场——货盘从 `itemPool/itemConfig/*.yaml` 分类池生成，`UpgradeSimulator`+`ScrollPatternGenerator` 模拟卷轴强化轨迹，按 WZ 价格×职业风格定价（`FMEconomyManager`），支持议价（`HaggleSession`），分 tier/热卖房。**货盘刻意走常规装备流，不含 PQ 专属奖励线**（阿尔泰耳环、海盗帽均不在任何池中；common 池耳环仅 1032001/1032026 两个普通变体）。

| 奖励表 | 生态位 | 判定 |
|---|---|---|
| PPQ 海盗帽 | bot 商店是「随机货+花钱+议价」，海盗帽是「肝碎片必得」的确定性目标，互补不冲突；55-100 正是机器人远征/PQ 主力等级段 | 有意义 |
| EPQ 阿尔泰耳环 | **耳环槽是 bot 经济的弱覆盖区**，v83 耳环位稀缺，阿尔泰链是唯一耳环成长线 | **意义最大，优先补** |

附加理由：机器人 PQ/远征上线后玩家会带 bot 队刷这两个 PQ，奖励表空着则机器人内容缺最后一环；「碎片→兑换」的目标驱动恰是机器人给不了的。

实现提醒：① EPQ 的 54,000 EXP 原版数值会被本服倍率体系衬得微不足道，需按倍率调校或明确「原汁原味」定位；② PPQ 击杀计数要防 bot 队刷分——建议只计玩家击杀（或玩家占比）。

## 4. 机器人化路线（按性价比排序）

### 4.0 结构性门槛三分类（单机+Bot 视角，先分清「为什么玩不了」）

**A 类——Bot 通路结构性够不着（需改架构）**：
- **APQ 婚礼**：`AmoriaPQ.js` `onlyMarriedPlayers=true`，硬校验 6 人全员已婚——bot 不结婚凑不齐。
- **GPQ 家族**：以公会为单位注册，bot 没有公会。
- **CWKPQ + 全部 Boss 远征**（扎昆/暗黑龙王/粉豆/昭和/斯卡尔塔迦/巴洛古…）：走 `Expedition` 远征系统报名，**不走组队邀请**——`BotPartySystem` 的入队通路够不着，需要远征适配层（见 4.1）。

**B 类——进得去、现有 Bot 池没人（配置级可修）**：HTPQ（120+ 固定 6）、TreasurePQ（140+）等高级内容——当前 bot 等级带仅 1-95（训练）与 50-70（OPQ 大厅），无 120+ bot；调整某波 cohort 等级带即可（注意：这两个也有 `use_enable_solo_expeditions` 单人开关，「进不去」严格说是「满不了员」）。

**C 类——能进能玩，但 Bot 只占位不干活（其余全部）**：HPQ/KPQ/LPQ/LMPQ/EFPQ/MPQ/PPQ 及自创 PQ——bot 能被邀请入队凑人数（等级带匹配），但只有 OPQBot 有打本状态机，其他 bot 进本保持原类型行为。且比「安静占位」更糟：TrainingBot 的选图带 `TrainingRegions` 白名单（PQ 地图不在内），进本后会「无处可去」，表现可能是原地徘徊/尝试回城/中途掉队——机器人陪打除了状态机，还需处理「进 PQ 期间挂起原 FSM」。

**单机玩家最痛缺口 = LPQ**（35-50，5 人本）：脚本现成、bot 等级带现成、凑 4 个 bot 的通路现成，缺的只是 LPQ 陪打状态机（8 关含数字密码箱，所有 PQ 中工作量最大，≈0.9×OPQ，且依赖 bot-NPC 对话原语）。

现状：仅 OPQ 有机器人支持——`soloMapling/ArtificialPlayer/BotTypes/OPQ/` 五件套（1836 行 = 1.0 基准：感知驱动状态机 + 1Hz 编排器黑板 + 共享上下文/常量/招募话术）。

### 4.1 远征线（最高优先，无新原语依赖）

**v1+v2 已落地（2026-09-17，未提交）**：`BotExpeditionRecruiter`（1Hz 扫描报名中的远征，入口图 BossRaidBot 自动 `addMember`，每队上限 6，通用所有远征类型）+ `BossRaidBot`（TrainingBot 子类复用 GrindBrain：入口站桩/进本战斗/怪不清不撤/副本结束回位）+ EnvironmentManager Wave 10（v1 Showa/Balrog；v2 全量：Zakum 211042400 六只 110-140、Horntail 240050400 六只 130-160、Scarga 551030100 六只 110-140、PinkBean 270050000 六只 150-180）。本地已验证：Wave 10 = 36 bots、六处入口各 6 只、等级带正确、全服 1255 bot。

**v2 关键发现：前置豁免天然免费**——远征 NPC 只对「来对话的真人」查等级/前置，成员入列走 `Expedition.addMember`（仅查人数/封禁/每日次数），bot 由 Recruiter 直接入列；扎昆火眼等前置道具只需队长真人持有。

## V3 计划（谜题型 PQ 机器人化，2026-09-17 制定）

**目标**：解锁 KPQ/LPQ/LMPQ/MPQ/EPQ 五个谜题型 PQ 的机器人陪打——前置是两个通用原语，其中 bot-NPC 对话模拟是整个机器人框架最后一块大公共缺口。

### Phase 0：验收与可观测性（先行，1-2 天）

前两版（远征/PQ 打怪型/练级加强）尚未做真实客户端验收，且「野外训练 bot 看不见」问题至今未定位（服务端确认分布在野区、1 频确认、仍不可见——怀疑出生包链路）。**如果战斗 bot 在客户端也不可见，后面全部白做**，故列首项：
- 六远征 + 六 PQ 的游戏内验收清单跑一遍（登记→入列→进图→输出）；
- 定位并修复野外 bot 不可见问题（复用 `!mapplayers` 二分法：服务端在列而客户端不见 → 查 `sendObjectPlacement`/spawn 广播；服务端不在列 → 查频道实例接线）；
- 后台在线列表加**频道列**（上次遗留的小改进，排障刚需）。

### Phase 1：两个通用原语（约 1 周）

- **原语 A：平台站位指派（0.1×OPQ）**——从 OPQ Orchestrator Stage2 的箱子分配器抽取通用 `PlatformAssignment`：编排器把「N 号平台」原子分给某 bot，bot 走过去站住。
- **原语 B：bot-NPC 对话模拟（0.3-0.4×OPQ，最大件）**——让 bot 能推进 NPC 会话。设计取向：**按 PQ 逐个适配**而非通用全自动（NPC 脚本是有状态会话，status/selection 千差万别）；做 `BotNpcDialogDriver`：注册「NPC id + 对话推进脚本」（到达哪个 status 选哪个选项、何时结束），复用 NPCScriptManager 的服务端路径（不模拟客户端封包），KPQ/LPQ 各写一份适配器验证原语。

### Phase 2：五个谜题型 PQ 逐个接入（每个 2-5 天，合计约 2 周）

| PQ | 工作量 | 依赖 | 关卡要点 |
|---|---|---|---|
| KPQ | 0.7 | A+B | Cloto 问答（算队里人数/职业数→站对应编号平台）+ 4 阶段推进 |
| LPQ | 0.9 | A+B | 9 层塔：打怪层直接打、平台顺序层用 A、密码层预置组合 |
| LMPQ | 0.8 | B+寻路 | 17 图迷宫：GCMove 传送门 BFS 寻路 + 打 reactor 开门 |
| MPQ | 0.8 | A+B | 玛加提亚 7 stage + Yulete 分支对话 |
| EPQ | 0.6 | A | reactor shuffle 型，对话需求最低 |

每接入一个 = `BotTypes/<PQ>/` 一套 stage 脚本包（OPQ 五件套模式）+ Wave 11 增加对应入口驻军。

### Phase 3：远征增强（观察项转正式，按需 2-4 天）

- 扎昆手臂定向分配（Phase 0 验收若发现集火单臂才做，OPQ 分配器改造）；
- Boss 图生存调优（嗑药阈值/HT 诱惑处置）；
- 远征/PQ 驻军规模与等级带进 `game_config`（热调，不改代码）。

### Phase 4（二期，独立立项）

CPQ1/2 + Ariant「对手队」——bot 从队友变对手，走 MonsterCarnival Java 侧，PvP 新范式。

**总计约 3-4 周量级；风险集中在原语 B 的会话模型匹配（按-PQ-适配策略已规避大半）与 Phase 0 的可见性问题（可能改变优先级）。**
